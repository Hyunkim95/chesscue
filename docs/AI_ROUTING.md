# Gemini routing for ChessCue

Chess.js establishes legality and board facts. Stockfish supplies candidate moves, evaluations, and checked continuations. ChessCue applies those facts to feedback, practice, and mastery. Gemini helps the player reason about the evidence. The pilot target is a 10 percentage-point lift in unaided skill transfer. The Review and Practice service objective is a complete verified explanation within 20 seconds (SLO-013).

## Route by task

| Route                            | Use it for                                                                                                                                                                                                                                                         | Fallback                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| Local rules and Stockfish        | Legal moves, attacks, comparisons, scoring, practice updates, and rendering or replaying checked lines. A question with a concrete board answer can use this route directly.                                                                                       | Show the verified part of the line or state what ChessCue could verify.                                                              |
| Gemini Nano via `ONLY_ON_DEVICE` | Interpret a short learner answer, select an evidence-backed hint or question, and adapt wording for one position. Give Nano a small set of checked facts and an answer schema.                                                                                     | Keep the board playable and use the checked explanation or an authored prompt.                                                       |
| Gemini Cloud via `ONLY_IN_CLOUD` | Explicitly requested archive research with tools, synthesis across several games, or a deeper explanation that benefits from more context. Send only the evidence needed for the task. Replay retrieved games and validate the output against the cited positions. | Keep the local or saved verified material available.                                                                                 |
| Firebase `PREFER_ON_DEVICE`      | A bounded, cloud-eligible prompt that can use the same contract on either route. Use it where the user has agreed to cloud processing of the inputs.                                                                                                               | Firebase can send the request to Cloud if Nano is unavailable. If the response fails validation, show the checked local explanation. |

Cloud can improve synthesis and retrieval. A stronger model still needs checked evidence to explain chess. If ChessCue can establish only that Stockfish prefers one move, show the comparison and describe which consequence the search established.

## Why the best move is good: Flash phrases a checked packet

Online, after a moment is solved or shown, "Why does it work?" opens on the point with two sentences from Gemini 3.8 Flash. Code first builds a reason packet with chess.js and Stockfish (`domain/analysis/why-packet.ts`): what the move takes and who can take back, pins and their pinning piece, what the move attacks or lines up, its threat if the opponent could pass, the top three defences, a recapture and the other way to take back, and what the game move allowed. Counts are the player's balance as fragments such as "3 points ahead". `domain/analysis/validate-why.ts` rejects moves, pieces and counts not in the packet, a wrong pinning piece, and "unstoppable", "forced" or "free" without support. Offline, on a timeout or on a rejection, the code caption stays. The whole answer must arrive within SLO-013's 20 seconds.

Evidence, 28 November 2026 (`research_notes/why-explanations/scorecard.md`, 20 positions, two blind model graders): Flash gave a true answer with the real reason in 16 of 20 positions and no false claim. Code-only text scored 8 of 20 and Flash-Lite 7 of 20, with 3 false. Nano was not measured for this task.

## Use Nano for a single teaching turn

The Firebase Web SDK exposes Nano as a single-turn generation route with structured text output. ChessCue owns the transcript and sends a bounded window of relevant turns when needed. This supports an ongoing conversation without assuming the SDK maintains native multi-turn chat. Include the exact position and the evidence behind the current claim. A compact prompt avoids context-window pressure and leaves room for a grounded answer. [Firebase hybrid Web capabilities](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started) · [Chrome Prompt API](https://developer.chrome.com/docs/ai/prompt-api)

A useful contract returns an intent label, a checked evidence ID, and optionally one short reflection question. Validate all three. Structured output checks the response shape. ChessCue still validates chess claims by replaying the board or matching known evidence. Reject unsupported moves, squares, and evaluations. An engine preference alone does not establish a causal explanation.

For example, after Qa4 or Qd2, Chess.js can show that both moves save the white queen. It can also show that Black’s Qa5 gives check after Qa4 and that the queen on d2 blocks the line to e1. For a follow-up of “why?”, render that difference directly. Nano can use the learner’s explanation to choose what to ask next. Repeating Stockfish’s preference gives the player no additional evidence.

## Account for device and privacy limits

- Check availability on the actual Chrome profile. Initialize Nano after a user gesture. Model installation depends on the browser and device, and the first download can take minutes. Keep cold-start, unsupported, offline, and failed-validation paths usable. [Firebase hybrid Web setup](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started)
- Use the SDK’s `inferenceSource` for provenance. An on-device response confirms the route. Model generation requires separate version evidence. [Firebase inference configuration](https://firebase.google.com/docs/ai-logic/hybrid/web/configuration-options)
- Firebase Web’s Nano path accepts text and supported inline images and returns text. It does not provide audio input, speech synthesis, or model tool calls on that path. The Rook demo uses browser speech recognition and narration. Sending a transcript to Nano, switching speech recognition online, and sending a transcript to Gemini Cloud are separate routing decisions. [Firebase Web route limits](https://firebase.google.com/docs/ai-logic/hybrid/web/get-started#features_not_yet_supported_for_on-device_inference)

Compare Nano with the same checked evidence and deterministic coaching as a baseline. Record factual correctness, complete explanations within the existing time limit, and unaided performance on new positions. For a Cloud route, use the same measures and verify what the extra context or tools improved. For route verification, use a real Chrome profile and confirm the inference source. A stubbed model checks UI behavior.
